## 프로젝트 목표

Push_swap 프로젝트는 주어진 정수 데이터를 두 개의 스택과 제한된 명령어들을 사용하여 정렬하는 알고리즘 프로젝트입니다. </br>
목표는 가장 적은 수의 명령어를 사용하여 스택을 정렬하는 프로그램을 C 언어로 작성하는 것입니다.

## 필수 파트

### 규칙

* 두 개의 스택 a와 b를 사용합니다.
    * 스택 a는 중복되지 않은 임의의 정수를 담고 시작합니다.
    * 스택 b는 비어있는 상태로 시작합니다.
* 목표는 스택 a의 정수를 오름차순으로 정렬하는 것입니다.
* 사용 가능한 명령어는 다음과 같습니다.
    * **sa** (swap a): 스택 a의 맨 위 두 요소를 교환합니다.
    * **sb** (swap b): 스택 b의 맨 위 두 요소를 교환합니다.
    * **ss**: sa와 sb를 동시에 실행합니다.
    * **pa** (push a): 스택 b의 맨 위 요소를 스택 a의 맨 위로 옮깁니다.
    * **pb** (push b): 스택 a의 맨 위 요소를 스택 b의 맨 위로 옮깁니다.
    * **ra** (rotate a): 스택 a의 모든 요소를 위로 1만큼 이동시킵니다. 맨 위 요소는 맨 아래로 갑니다.
    * **rb** (rotate b): 스택 b의 모든 요소를 위로 1만큼 이동시킵니다. 맨 위 요소는 맨 아래로 갑니다.
    * **rr**: ra와 rb를 동시에 실행합니다.
    * **rra** (reverse rotate a): 스택 a의 모든 요소를 아래로 1만큼 이동시킵니다. 맨 아래 요소는 맨 위로 갑니다.
    * **rrb** (reverse rotate b): 스택 b의 모든 요소를 아래로 1만큼 이동시킵니다. 맨 아래 요소는 맨 위로 갑니다.
    * **rrr**: rra와 rrb를 동시에 실행합니다.

### 예시

주어진 명령어들을 사용하여 정수 리스트를 정렬하는 예시가 제공됩니다.

### "push_swap"프로그램

* 프로그램 이름: push_swap
* 제출 파일: Makefile, *.h, *.c
* Makefile 규칙: NAME, all, clean, fclean, re
* 인수: 스택 a의 정수 리스트
* 사용 가능 함수: read, write, malloc, free, exit, ft_printf (직접 구현한 유사 함수 허용)
* Libft 사용: 허용
* 설명: 스택 정렬
* 주의사항:
    * Makefile은 relink하면 안 됩니다.
    * 전역 변수 사용은 금지됩니다.
    * 프로그램은 스택 a를 정렬하는 가장 짧은 명령어 목록을 출력해야 합니다.
    * 명령어는 '\n'으로 구분해야 합니다.
    * 가장 적은 수의 연산으로 스택을 정렬하는 것이 목표입니다.
    * 잘못된 입력이 주어지면 "Error"를 출력해야 합니다.

### 벤치마크

과제 검증을 위해 특정 횟수 내에 정렬을 수행해야 합니다.

* 최소 검증 (80점 이상): 100개의 무작위 숫자를 700회 미만의 연산으로 정렬.
* 최대 검증 (보너스 점수 획득): 500개의 무작위 숫자를 5500회 미만의 연산으로 정렬.

## 보너스 과제

자체 checker 프로그램을 만드는 것이 보너스 과제입니다. </br>
이 프로그램은 push\_swap 프로그램이 생성한 명령어 목록이 실제로 스택을 올바르게 정렬하는지 확인합니다. </br>
보너스 과제는 필수 과제가 완벽하게 구현되고 모든 벤치마크를 통과한 경우에만 평가됩니다.

### "checker" 프로그램

* 프로그램 이름: checker
* 제출 파일: \*.h, \*.c
* Makefile 규칙: bonus
* 인수: 스택 a의 정수 리스트
* 사용 가능 함수: read, write, malloc, free, exit, ft\_printf (직접 구현한 유사 함수 허용)
* Libft 사용: 허용
* 설명: 정렬 명령어 실행
* 주의사항:
    * 프로그램은 스택 a를 인수로 받고, 표준 입력으로 명령어를 읽어 실행합니다.
    * 모든 명령어를 실행한 후, 스택 a가 정렬되고 스택 b가 비어있으면 "OK"를 출력하고, 그렇지 않으면 "KO"를 출력합니다.
    * 잘못된 입력이나 명령어가 주어지면 "Error"를 출력해야 합니다.
    * 제공된 바이너리와 정확히 동일하게 동작할 필요는 없지만, 오류 처리는 필수입니다.
